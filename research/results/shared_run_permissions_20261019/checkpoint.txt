Shared run-file permission correction

The tracked agent settings own the permissions for every new worktree from the updated base.
Codex defaults to math and the external launcher selects math, extending :workspace with one
dedicated shared directory. Claude lists the same directory among its working directories and
allows Edit on the worktree paths, main aliases and resolved files. Other main-checkout files
are not writable from a Codex worktree. Existing sessions retain their saved permission profile.

The main aliases user_requests and run_state now link into .shared-run-files. Existing worktree
links continue through those aliases. Migration first hard-linked the original files, then
atomically replaced the main aliases with symlinks; inode, mode, byte count and SHA-256 checks
before and after matched. The shared directory is machine-local and ignored by Git.

Two earlier designs were wrong: the inventory installer required repetition for new paths,
and native Codex individual-file grants failed while constructing metadata protection paths
beneath files. The inventory installer is deleted. Extending :workspace with a directory grant
passed the native check. The temporary shared-file Bash refusal is removed.

The Claude dontAsk probe refused Bash; it is not counted as a success. After adding the shared
working directory, the auto-mode probe with permission-prompts none executed the zero-byte
append, returned a successful tool_result, and reported no permission denials. Framework hooks
were disabled only in that isolated native-permission probe; file permissions remained active.
The retained Claude evidence projects tool calls/results, excluding private initialization data.

Prevention: tools/tests/shared_permissions_smoke.sh exercises the native default profile with
actual append opens through both symlinks, checks unrelated main files and workspace metadata
remain read-only, and requires the built-in :workspace control to reject the same append.
The launcher regression checks selection of the project's math profile.

Integration completed: a fresh detached worktree was created from the synchronized source
checkpoint, with no copied settings and no permission installer. From that working directory,
the native Codex default profile opened the main shared aliases for zero-byte append while
unrelated main files and workspace metadata remained read-only. Native Claude auto mode opened
the same aliases with no permission denials. See fresh-worktree-codex.txt and
fresh-worktree-claude.jsonl. The test worktree was then removed.

Base synchronization brought concurrent framework changes requiring Python 3.15 and setting
the suite limit to fifteen seconds. The integrated-suite.txt run uses that interpreter and
the project limit, with twelve workers; the earlier Python 3.12 run failed to import the
new symbol check's Python 3.15 tree-sitter binding. The final symbol-use check passes.
The earlier worker-count comparison is retained: eight workers reduced CPU contention but
extended wall time; twelve passed the then-current ten-second limit. No suite limit was
changed by this permission correction.

Timing begins after the initial configuration investigation. Preparation includes approval
interruptions and support for the user's terminal commands; those intervals are not separate
measurements of engineering work. Final checkpoint operations follow the timing snapshot.
Raw runtime traces remain local because they contain private initialization and scratch data.

Meta: permission changes belong in inherited project configuration and must be checked through
the native runtime. JSON/TOML parsing and edits to temporary settings are not evidence that a
write is authorized. A local runtime failure is an implementation finding to resolve, not an
endpoint to hand back to the user. tools/CODEX.md now names the native check for these changes.
